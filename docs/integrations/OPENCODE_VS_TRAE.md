## 🎯 OpenCode 的工作模式（正确理解）

### 核心理念

**OpenCode 不需要调度员 AI！**

OpenCode（OpenClaw/龙虾）的工作模式是：
- **人类**：给一个初始指令
- **zen AI**：持续运行的 AI 实例，自己执行任务
- **自动化**：读取 HEARTBEAT.md → 执行任务 → 产生新任务 → 循环

### 单 AI 持续工作架构

```
┌─────────────────────────────────────────────────────────┐
│                    OpenCode 架构                         │
│                                                          │
│  ┌─────────────────────────────────────────────────┐    │
│  │              zen AI (持续运行)                    │    │
│  │                                                   │    │
│  │  1. 读取 HEARTBEAT.md                            │    │
│  │  2. 执行任务                                      │    │
│  │  3. 代码评审，发现新问题                          │    │
│  │  4. 产生新任务，更新 HEARTBEAT.md                 │    │
│  │  5. 循环...                                       │    │
│  │                                                   │    │
│  └─────────────────────────────────────────────────┘    │
│                          │                              │
│                          ▼                              │
│              ┌─────────────────────┐                    │
│              │   HEARTBEAT.md      │                    │
│              │   (任务清单)         │                    │
│              └─────────────────────┘                    │
└─────────────────────────────────────────────────────────┘
```

### 关键点

1. **zen AI 不是调度员**
   - zen AI 是一个持续运行的 AI 实例
   - 它自己执行任务，不是分配任务给别人

2. **serv 不是独立的 AI**
   - serv 是 zen AI 分配给具体任务的执行
   - 本质上还是同一个 AI

3. **人类只是给初始指令**
   - 人类不需要持续监控
   - 给一个指令后，AI 自动循环工作

## 🎯 Trae 的工作模式

### 单 AI 模式（无持续运行）

Trae 采用**单 AI 模式**：

```
┌─────────────────────────────────────────────────────────┐
│                    Trae 架构                             │
│                                                          │
│  ┌─────────────────────────────────────────────────┐    │
│  │              Trae AI (单实例)                     │    │
│  │                                                   │    │
│  │  - 等待用户触发                                   │    │
│  │  - 执行任务                                       │    │
│  │  - 报告结果                                       │    │
│  │                                                   │    │
│  │  ⚠️ 没有持续运行的服务                             │    │
│  │  ⚠️ 需要用户手动触发                              │    │
│  └─────────────────────────────────────────────────┘    │
│                        │                                │
│                        ▼                                │
│              ┌─────────────────────┐                    │
│              │   用户手动触发       │                    │
│              └─────────────────────┘                    │
└─────────────────────────────────────────────────────────┘
```

### 关键限制

- ❌ **无持续运行**: AI 不持续运行
- ❌ **需要手动触发**: 需要用户手动触发
- ❌ **无自主任务闭环**: 不能自主产生任务闭环

## 🎯 如何在 Trae 中实现类似 OpenCode 的工作模式？

### 正确的方案: HeartbeatService + Trae AI

**架构**:

```
┌─────────────────────────────────────────────────────────┐
│              正确的 Nezha + Trae 架构                    │
│                                                          │
│  ┌─────────────────────────────────────────────────┐    │
│  │         HeartbeatService (持续运行)              │    │
│  │                                                   │    │
│  │  1. 读取任务（从数据库或文件）                     │    │
│  │  2. 调用 Agent（编辑器 AI）执行任务               │    │
│  │  3. 等待 Agent 返回结果                           │    │
│  │  4. 更新任务状态                                  │    │
│  │  5. 循环...                                       │    │
│  │                                                   │    │
│  │  注意：HeartbeatService 是服务，不是调度员！       │    │
│  │  它的工作是查询和调用，不是分配任务给别人！         │    │
│  └─────────────────────────────────────────────────┘    │
│                          │                              │
│                          ▼                              │
│              ┌─────────────────────┐                    │
│              │  PostgreSQL/文件     │                    │
│              │  (任务存储)          │                    │
│              └─────────────────────┘                    │
└─────────────────────────────────────────────────────────┘
```

**关键区别**:

| 维度 | OpenCode | Nezha + Trae |
|------|----------|--------------|
| **持续运行** | zen AI 实例 | HeartbeatService 服务 |
| **任务执行** | zen AI 自己执行 | 调用编辑器 AI 执行 |
| **任务存储** | HEARTBEAT.md | PostgreSQL 或文件 |
| **调度员** | ❌ 不需要 | ❌ 不需要 |
| **人类角色** | 给初始指令 | 给初始指令 |

## 🎯 实施方案

### 方案 1: 文件模式（Nezha 自身项目）

**适用场景**: Nezha 自身的开发和维护

**工作流程**:
```
人类给初始指令
    ↓
AI 读取 HEARTBEAT.md
    ↓
AI 执行任务
    ↓
AI 代码评审，发现新问题
    ↓
AI 更新 HEARTBEAT.md
    ↓
AI 继续读取 HEARTBEAT.md
    ↓
循环...
```

**实施步骤**:
1. 创建 `HEARTBEAT.md` 文件
2. AI 每次被用户触发时，读取文件
3. 执行最高优先级的任务
4. 发现新问题，添加新任务
5. 提交更改

### 方案 2: 数据库模式 + HeartbeatService（其他项目）

**适用场景**: 管理 Nezha 之外的其他项目

**工作流程**:
```
人类给初始指令
    ↓
HeartbeatService 持续运行
    ↓
HeartbeatService 查询数据库中的任务
    ↓
HeartbeatService 调用 Agent 执行任务
    ↓
Agent 执行任务并产生新任务
    ↓
Agent 将新任务写入数据库
    ↓
HeartbeatService 继续查询
    ↓
循环...
```

**实施步骤**:
1. 启动 HeartbeatService
   ```bash
   # 使用 PM2 运行
   pm2 start dist/cli/index.js --name nezha-heartbeat
   
   # 查看状态
   pm2 status
   
   # 查看日志
   pm2 logs nezha-heartbeat
   ```

2. HeartbeatService 的工作
   - 持续运行心跳服务
   - 查询数据库中的待处理任务
   - 调用 Agent 执行任务
   - 更新任务状态

3. Agent（编辑器 AI）的工作
   - 执行具体任务
   - 代码评审，发现新问题
   - 产生新任务并写入数据库
   - 报告执行结果

## 📊 对比总结

| 维度 | OpenCode | Trae (当前) | Trae + Nezha |
|------|----------|------------|--------------|
| **持续运行** | ✅ zen AI 持续运行 | ❌ 无 | ✅ HeartbeatService 持续运行 |

| **自主产生任务** | ✅ zen AI 自主产生 | ❌ 无 | ✅ AI 自主产生 |
| **闭环工作** | ✅ 持续循环 | ❌ 手动触发 | ✅ 持续循环 |
| **调度员** | ❌ 不需要 | ❌ 无 | ❌ 不需要 |
