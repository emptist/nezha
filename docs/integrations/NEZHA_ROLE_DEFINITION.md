# Nezha 角色定义

**创建日期**: 2026-03-17  
**版本**: 1.0  
**目的**: 明确 Nezha 在系统中的角色和定位

---

## 🎯 Nezha 的核心定位

**Nezha（哪吒）是一个调度和记忆工具**，它的作用是：

1. **帮助** 大模型更好地工作
2. **激发** 大模型的自主性和创造力
3. **监测** 大模型的工作状态和进展

**Nezha 不是工作者，而是工具和助手。**

---

## 👥 角色分工

### Nezha 的角色：调度器和记忆工具

**职责**:
- 📋 **任务调度**: 从数据库获取任务，调度大模型执行
- 💾 **记忆管理**: 存储和检索知识、经验、配置
- 📊 **状态监测**: 监控任务执行状态、系统健康
- 🔧 **环境准备**: 准备工作环境、配置、工具
- 📈 **进展跟踪**: 记录工作进展、成果、问题

**不做什么**:
- ❌ 不直接执行任务（如写代码、分析问题）
- ❌ 不做决策（决策由大模型完成）
- ❌ 不创造内容（内容由大模型创造）
- ❌ 不解决问题（问题由大模型解决）

### 大模型的角色：工作者和决策者

**职责**:
- 🎨 **设计**: 设计系统架构、解决方案
- 📚 **学习**: 学习新知识、技能、最佳实践
- ✍️ **创作**: 编写代码、文档、测试
- 🔍 **评审**: 审查代码、设计、文档
- 📤 **提交**: 提交代码、文档、配置
- 🚀 **发布**: 发布版本、部署系统

**如何工作**:
- ✅ 自主决策如何完成任务
- ✅ 自主选择工具和方法
- ✅ 自主学习和改进
- ✅ 自主处理遇到的问题

## 🔄 工作流程

### 标准工作流程

```
Nezha (调度器)                大模型 (工作者)
     │                              │
     ├─ 1. 获取任务                 │
     │   (从数据库)                 │
     │                              │
     ├─ 2. 准备环境                 │
     │   (配置、工具)               │
     │                              │
     ├─ 3. 提供记忆                 │
     │   (历史经验、知识)           │
     │                              │
     ├─ 4. 调度执行 ────────────────►│
     │                              │
     │                              ├─ 5. 理解任务
     │                              │   (分析需求)
     │                              │
     │                              ├─ 6. 制定计划
     │                              │   (决策方法)
     │                              │
     │                              ├─ 7. 执行工作
     │                              │   (设计、编码、测试)
     │                              │
     │                              ├─ 8. 处理问题
     │                              │   (自主解决)
     │                              │
     │                              ├─ 9. 完成任务
     │                              │   (提交成果)
     │                              │
     ├◄─────────────────────────────┤
     │                              │
     ├─ 10. 记录结果                │
     │   (存储记忆)                 │
     │                              │
     ├─ 11. 更新状态                │
     │   (任务状态)                 │
     │                              │
     └─ 12. 继续下一个任务          │
```

### 关键原则

1. **Nezha 不干预**: Nezha 只提供工具和记忆，不干预大模型的决策
2. **大模型自主**: 大模型完全自主地决定如何完成任务
3. **持续循环**: 工作是持续的，一个任务完成后自动开始下一个
4. **知识积累**: 每次工作的经验都被记录，形成知识库

## 🛠️ Nezha 的核心功能

### 1. 帮助 (Help)

**如何帮助大模型**:

- **提供记忆**: 在大模型开始工作前，提供相关的历史经验和知识
  ```typescript
  // 示例：提供数据库连接记忆
  const memory = await memoryService.search("database connection");
  // 返回：上次成功的连接配置、遇到的问题、解决方案
  ```

- **准备环境**: 自动准备工作所需的环境、工具、配置
  ```typescript
  // 示例：检测并配置数据库连接
  const dbConfig = await detectDatabaseConfig();
  // 自动检测：APP安装、Keychain认证、正确的连接参数
  ```

- **提供上下文**: 提供任务的完整上下文，包括项目状态、依赖关系
  ```typescript
  // 示例：提供项目上下文
  const context = await getProjectContext();
  // 返回：项目结构、最近变更、待办事项、相关文档
  ```

### 2. 激发 (Trigger)

**如何激发大模型**:

- **任务提示**: 提供清晰的任务描述和期望结果
  ```typescript
  // 示例：任务提示
  task.description = `
  Review and improve the authentication system:
  1. Analyze current implementation
  2. Identify security vulnerabilities
  3. Propose improvements
  4. Implement fixes
  5. Write tests
  6. Update documentation
  `;
  ```

- **挑战设置**: 设置适当难度的挑战，激发创造力
  ```typescript
  // 示例：挑战设置
  task.challenge = `
  Optimize the database query performance by at least 50%
  while maintaining code readability and test coverage.
  `;
  ```

- **灵感提供**: 提供相关的最佳实践、案例研究、创新思路
  ```typescript
  // 示例：灵感提供
  task.inspiration = `
  Consider using:
  - Caching strategies (Redis, in-memory)
  - Query optimization (indexes, denormalization)
  - Async processing (queues, workers)
  `;
  ```

### 3. 监测 (Monitor)

**如何监测大模型**:

- **进度跟踪**: 实时跟踪任务执行进度
  ```typescript
  // 示例：进度跟踪
  const progress = await getTaskProgress(taskId);
  // 返回：已完成步骤、当前状态、预计剩余时间
  ```

- **健康检查**: 监控系统和大模型的健康状态
  ```typescript
  // 示例：健康检查
  const health = await checkSystemHealth();
  // 返回：数据库连接、API 可用性、资源使用情况
  ```

- **异常检测**: 检测异常情况并及时报警
  ```typescript
  // 示例：异常检测
  if (task.duration > expectedDuration * 2) {
    await alert("Task taking too long, may be stuck");
  }
  ```

- **质量评估**: 评估工作成果的质量
  ```typescript
  // 示例：质量评估
  const quality = await assessWorkQuality(task.result);
  // 返回：代码质量、测试覆盖率、文档完整性
  ```

## 📚 记忆系统设计

### 记忆类型

1. **系统记忆** (System Memory)
   - 环境配置（数据库连接、API密钥）
   - 系统状态（服务状态、资源使用）
   - 成功经验（成功的配置、方法）

2. **任务记忆** (Task Memory)
   - 任务历史（完成的任务、结果）
   - 问题解决（遇到的问题、解决方案）
   - 最佳实践（有效的方法、模式）

3. **知识记忆** (Knowledge Memory)
   - 领域知识（技术栈、框架、库）
   - 项目知识（架构、设计决策）
   - 经验教训（失败案例、教训）

### 记忆存储

- **数据库**: 结构化存储，支持查询和搜索
- **文件系统**: 非结构化存储，人类可读
- **向量存储**: 语义搜索，相似性匹配

### 记忆检索

- **主动检索**: 在大模型开始工作前，主动提供相关记忆
- **智能推荐**: 根据任务类型，推荐相关的知识和经验
- **上下文感知**: 根据当前状态，提供最相关的记忆

## 🎯 成功指标

### Nezha 的成功指标

- **调度效率**: 任务调度是否及时、准确
- **记忆命中率**: 提供的记忆是否有用
- **环境准备成功率**: 环境准备是否成功
- **监测准确性**: 监测是否及时、准确

### 大模型的成功指标

- **任务完成率**: 任务是否按时、按质完成
- **问题自主解决率**: 遇到问题是否自主解决
- **学习效率**: 是否快速学习新知识
- **创新能力**: 是否有创新性的解决方案

## 💡 关键洞察

### Nezha vs OpenClaw

| 维度 | OpenClaw | Nezha |
|------|----------|-------|
| 角色 | 单一 AI 实例 | 调度器 + 记忆工具 + AI |
| 记忆 | HEARTBEAT.md | 数据库 + 文件系统 |
| 调度 | AI 自己调度 | Nezha 调度 AI |
| 监测 | AI 自己监测 | Nezha 监测 AI |
| 帮助 | AI 自己帮助自己 | Nezha 帮助 AI |

**Nezha 的优势**:
- ✅ 职责分离：调度和工作分离，更清晰
- ✅ 持久记忆：数据库存储，更可靠
- ✅ 专业工具：专门的调度和记忆工具，更高效
- ✅ 可扩展：可以调度多个 AI 实例，支持并行工作

**OpenClaw 的优势**:
- ✅ 简单统一：一个 AI 完成所有事情
- ✅ 自包含：不依赖外部工具
- ✅ 灵活：AI 可以自由发挥
